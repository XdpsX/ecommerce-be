# FE handoff: API map và màn hình admin trước

Ngày đối chiếu backend: 2026-10-04. Nguồn sự thật là controller, request/response DTO và security config hiện tại trong `src/main/java`. Đây là tài liệu bàn giao API cho FE, không phải OpenAPI contract mới. [Danh mục màn hình đầy đủ](./screen-inventory.md) và các brief [Backoffice](./backoffice-screen-brief.md), [Storefront](./storefront-screen-brief.md) là đầu vào ngắn gọn cho AI Figma. Ký hiệu **Có** = route đang tồn tại; **Đề xuất** = chưa có route hoặc cần đổi contract. M1 là **single-store**, chỉ có `USER` và `ADMIN`; giao diện dùng tiếng Việt, tiền tệ VND.

## 1. Nguyên tắc chung cho FE

- Base URL local mặc định `http://localhost:8080` (có thể đổi bằng `SERVER_PORT`); backend không khai báo context path. Dùng một biến cấu hình `API_BASE_URL`, không ghép `/api` nếu backend chưa thêm prefix.
- API cần đăng nhập nhận `Authorization: Bearer <accessToken>`. `POST /auth/login` trả `{accessToken}` và set refresh credential bằng cookie HttpOnly. Sau reload, gọi `POST /auth/refresh` với `credentials: include` và header `X-Session-Request: 1`, rồi gọi `GET /users/me` để biết `role`. `POST /auth/logout` dùng cùng cookie/header. Không đọc hoặc lưu refresh credential trong JS. Admin shell chỉ cho `role=ADMIN`; backend vẫn là nơi kiểm quyền.
- Nếu FE và API khác origin, cấu hình CORS origin ở backend, dùng `credentials: include` cho refresh/logout và guest cart. Cookie mặc định `Secure`; môi trường local HTTP cần cấu hình phù hợp. Đừng giả định OAuth trả cùng loại session với LOCAL; xác nhận flow đó riêng trước khi làm nút social login.
- Danh sách có phân trang dùng `{ data: T[], meta: { page, size, totalElements, totalPages } }`. Catalog dùng `pageNum` từ 1, `pageSize` từ 5 đến 20 (mặc định 7), `sort=name|-name|date|-date`, riêng product thêm `price|-price`. Order list dùng `pageNum`/`pageSize`, mặc định 1/5. Danh sách variant option, storefront category/brand, address là array trực tiếp.
- Lỗi do backend kiểm soát theo Problem Details: đọc `status`, `title`, `detail`, `code` và có thể có `parameters`. FE cần xử lý 401 (refresh/relogin), 403 (không đủ quyền), 404, 409 (reload dữ liệu rồi thông báo xung đột), 400 (validation). Không suy ra thành công chỉ từ HTTP 200 nếu nội dung nghiệp vụ còn `PENDING`.
- Money là decimal VND: giữ dạng chuỗi/thư viện decimal khi nhập và hiển thị; không tính lại giá chốt đơn từ giá catalog hiện tại. Thời gian là `Instant` hoặc `LocalDateTime` tùy DTO; format theo múi giờ người dùng, không tự gán `Z` cho `LocalDateTime`.

## 2. Backoffice: bản đồ API hiện có

Các đường dẫn dưới đây là đường dẫn thật, bao gồm ba endpoint admin của Order vẫn ở `/orders`.

| Nhóm | API **Có** | Input / response quan trọng | Dùng ở màn hình |
| --- | --- | --- | --- |
| Auth | `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`, `GET /users/me` | Login `{email,password}` → `{accessToken}`; profile có `role` | A0, admin shell |
| Category | `GET /admin/categories`, `GET /admin/categories/{id}` | Filter `name,status,parentId,level,sort,pageNum,pageSize`; item `{id,name,slug,status,version,effectivelyActive,displayOrder,image,parent}` | A1 |
| Category write | `POST /admin/categories`, `PUT /admin/categories/{id}`, `PUT /admin/categories/{id}/parent`, `PUT /admin/categories/order`, `DELETE /admin/categories/{id}` | Tạo `{name,status,imageId,parentId}`; sửa `{name,status,slug?,imageId?,version}`; move `{parentId,position}`; reorder `{parentId,categoryIds}` (toàn bộ sibling group); delete body `{version}` | A1 |
| Brand | `GET /admin/brands`, `GET /admin/brands/{id}`, `POST /admin/brands`, `PUT /admin/brands/{id}`, `DELETE /admin/brands/{id}` | Filter `name,status,sort,pageNum,pageSize`; item có `version,image,categories`; create/update `{name,status,imageId,categoryIds}`, update/delete cần `version` | A2 |
| Variant option | `GET /admin/variant-options`, `GET /admin/variant-options/{id}`, `POST /admin/variant-options`, `PUT /admin/variant-options/{id}`, `POST /admin/variant-options/{optionId}/values`, `PUT /admin/variant-options/{optionId}/values/{valueId}`, `PUT /admin/variant-options/{optionId}/values/order` | Option/value có `code,name,displayOrder,status`; reorder gửi `{valueIds}` theo thứ tự mới | A3 |
| Product | `GET /admin/products`, `GET /admin/products/{id}`, `GET /admin/products/slug-availability?slug=`, `POST /admin/products`, `PUT /admin/products/{id}`, `PATCH /admin/products/{id}/publication`, `DELETE /admin/products/{id}` | List filter `search,hasPublished,sort,pageNum,pageSize`; item có giá min/max trên Variant ACTIVE và tổng `onHand,reserved,available`; slug create/update/availability dùng canonical slug. Create `{name,slug,description,categoryId,brandId,imageIds}`; update tương tự; publication `{published}` | A4, A5 |
| SKU / price | `GET /admin/products/{productId}/variants`, `POST /admin/products/{productId}/variants`, `PUT /admin/products/{productId}/variants/{variantId}/barcode`, `PATCH .../{variantId}/price`, `PATCH .../{variantId}/status`, `PUT .../{variantId}/sale`, `DELETE .../{variantId}/sale` | Batch create `{variants:[{sku,barcode,basePrice,optionValueIds}]}`; price `{basePrice}`; status `{status}`; sale `{salePrice,currency:"VND",startsAt,endsAt}`. Response có giá gốc, sale, giá cuối, status và option IDs | A5 |
| Inventory | `GET /admin/inventory/variants/{variantId}`, `POST /admin/inventory/variants/{variantId}/adjustments` | Balance `{variantId,sku,onHand,reserved,available}`; adjustment `{quantityDelta,reason}` (delta khác 0) | A5, A6 |
| Media | `POST /media/image-upload?resource=category|brand|product`, `DELETE /media/{id}` | `multipart/form-data` gồm `file`, `caption?`; response `{id,caption,contentType,url}`. Dùng `id` cho `imageId`/`imageIds`, dùng `url` để preview | A1, A2, A4 |
| Order | `GET /orders?pageNum=&pageSize=&orderStatus=&paymentStatus=&trackingNumber=`, `GET /orders/{orderId}`, `PATCH /orders/{id}/status`, `POST /admin/orders/{orderId}/cancellation` | Admin list `OrderDTO` có tracking, status, paymentStatus, total/currency, shipping snapshot, thời gian, refund summary; exact tracking search; page size 1–20; detail thêm `username,items`; status body `{status}`; cancel `{reason}` | A7, A8 |
| Refund | `GET /admin/refunds?status=&pageNum=&pageSize=`, `GET /admin/refunds/{refundId}`, `POST /admin/refunds/{refundId}/complete`, `POST /admin/refunds/{refundId}/fail`, `POST /admin/refunds/{refundId}/retry` | Queue trả `id,orderId,trackingNumber,status,amount,currency,reason,requestedAt`, sort oldest first; mutation giữ nguyên. Complete body tùy chọn `{externalReference}`; fail `{failureReason}`; retry không body | A8, A9 |

Admin order status cho phép forward fulfillment `CONFIRMED → PROCESSING → SHIPPED → DELIVERED`. Admin cancel khi `PENDING_PAYMENT`, `CONFIRMED` hoặc `PROCESSING`, luôn nhập lý do; sau `SHIPPED` không có return/RTO trong M1. Refund là tác vụ thủ công: `PENDING → SUCCEEDED` hoặc `FAILED → PENDING` qua retry. Không thiết kế nút “hoàn tiền tự động qua VNPay”.

## 3. Backoffice: mô tả màn hình cho AI thiết kế

Thiết kế desktop trước ở 1440px; việc vẽ tablet 768px cần chốt theo [ma trận kích thước](./screen-inventory.md#kích-thước-viewport-và-quyết-định-có-vẽ-frame-riêng). Tông sạch, tập trung thao tác vận hành; thể hiện rõ thông tin tiền và trạng thái, xác nhận trước hành động có hậu quả. Sidebar: Tổng quan, Danh mục, Thương hiệu, Thuộc tính SKU, Sản phẩm, Đơn hàng, Hoàn tiền. Refund có hàng đợi riêng qua `GET /admin/refunds` và vẫn mở được từ chi tiết đơn. Không tạo menu “Khách hàng”, “Báo cáo”, “Vận chuyển” như chức năng đã chạy. Mọi list có loading skeleton, empty state, lỗi tải lại, phân trang nếu API có hỗ trợ. Bảng sau là mô tả gọn; danh mục và brief liên kết ở đầu file là bản đặc tả màn hình để gửi AI Figma.

## 4. Storefront: API và màn hình vòng đầu

Phần này là inventory ngắn để định hình design system và API client. Ưu tiên triển khai chi tiết sau admin. Trong [danh mục màn hình](./screen-inventory.md), S3, S4 và S8 được tách thành `a/b` để phân biệt các bề mặt cần thiết kế.

| Luồng | API **Có** | Màn hình đề xuất |
| --- | --- | --- |
| Khám phá catalog | `GET /categories`, `/categories/tree`, `/categories/{slug}`, `/brands?categoryId=`, `/products`, `/products/latest`, `/products/filter-options`, `/products/slug/{slug}` | S0 Trang chủ: category và sản phẩm mới; S1 PLP: search, category/brand/price/stock/option filter, sort, pagination; S2 PDP: ảnh, option→SKU, giá thực tế, trạng thái còn hàng, add to cart |
| Auth & profile | `POST /auth/register`, `/login`, `/refresh`, `/logout`; `GET/PATCH /users/me`; `GET/POST /users/me/addresses`, `PUT/DELETE /users/me/addresses/{addressId}` | S3 Đăng nhập/đăng ký; S4 hồ sơ và sổ địa chỉ. Address CRUD thuộc chủ tài khoản, không có admin user management |
| Cart | `GET /cart`, `POST /cart/items`, `PUT/DELETE /cart/items/{variantId}`, `POST /cart/claim` | S5 Cart cho guest/customer; item có availability `AVAILABLE`, `UNAVAILABLE` hoặc `INSUFFICIENT_STOCK`, estimate price; claim guest cart sau đăng nhập |
| Checkout & payment | `POST /checkout` với header `Idempotency-Key`, body `{addressId,description?}`; `POST /orders/{orderId}/payment-attempts`; `GET /payments/vnpay_ipn` dành cho VNPay server callback | S6 Checkout chọn địa chỉ, xem lại cart và submit; S7 chuyển hướng đến `payment.vnpUrl`, quay lại xem trạng thái đơn; retry payment attempt từ order pending, không gọi IPN từ browser |
| Đơn của tôi | `GET /orders/me`, `GET /orders/code/{trackingNumber}`, `POST /orders/{orderId}/cancellation` | S8 danh sách/chi tiết đơn, trạng thái thanh toán/refund; chỉ hiện cancel khi `PENDING_PAYMENT` hoặc `CONFIRMED`, nhập reason |

`GET /products` hỗ trợ `search,sort,minPrice,maxPrice,inStock,categoryId,brandId,optionValueIds,pageNum,pageSize`. Khi FE lọc option hoặc giá, option, effective price và `inStock=true/false` phải khớp cùng một SKU; nếu chỉ gửi `inStock=false`, Product chỉ khớp khi tất cả SKU đủ điều kiện đều hết hàng. Khi kết hợp với option/giá, điều kiện `inStock` áp lên SKU khớp các filter đó. Trường response `inStock` vẫn là availability toàn Product (có ít nhất một SKU đủ điều kiện đang còn hàng): Product có thể khớp qua SKU hết hàng nhưng trả `inStock=true` vì SKU đủ điều kiện khác còn hàng; không dùng cờ này để suy ra availability của riêng SKU đang lọc. `minimumPrice/maximumPrice` trong PLP vẫn là range toàn Product, không thu hẹp theo filter. Product slug mới được chuẩn hóa lowercase ASCII; legacy slug tiếp tục đọc được. PDP trả `variants` với `variantId`, `optionValueIds`, `finalUnitPrice` và `available`; FE chọn đúng tổ hợp rồi dùng `variantId` để add cart. Cart guest mutation cần header `X-Cart-Request: 1` và cookie; claim cần login. Checkout trả `{order,payment,replayed}`; nếu lỗi `PAYMENT_INITIALIZATION_FAILED` sau khi Order commit, BE trả Order cùng `payment: null`; retry cùng key sẽ thử lại payment attempt. Giá trong cart là ước tính, giá trong order là snapshot.

## 5. Prompt ngắn để gửi AI thiết kế

> Thiết kế giao diện e-commerce single-store bằng tiếng Việt, **backoffice/admin trước**. Lấy [danh mục màn hình](./screen-inventory.md) làm checklist và dùng brief [Backoffice](./backoffice-screen-brief.md), [Storefront](./storefront-screen-brief.md) làm đầu vào cho từng nhóm frame. Phân biệt API **Có** với **Đề xuất**: chỉ thiết kế dữ liệu/thao tác đã có backend như hoạt động thật; đánh dấu các phần cần API mới là future state. Không vẽ dashboard KPI đang hoạt động. Không thêm marketplace, multi-vendor, voucher engine, giao hàng tích hợp hoặc hoàn tiền tự động.

Trước khi code FE, dùng OpenAPI runtime (`/v3/api-docs` và Swagger UI khi backend chạy) để đối chiếu schema cuối cùng. Tài liệu này bám code hiện tại; nếu backend đổi route/DTO, cập nhật bảng API và màn hình liên quan trong cùng CR.
